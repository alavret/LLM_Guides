## 3. Установка базовых правил работы агента
Hermes Agent использует файловую систему для хранения инструкций, которые добавляются в запрос пользователя, чтобы контролировать поведение модели.

[Табличка из документации](https://hermes-agent.nousresearch.com/docs/user-guide/features/context-files#supported-context-files)

| Supported Context Files | File |	Purpose	Discovery |
| :--- | :------: | ----: |
|.hermes.md / HERMES.md	| Project instructions (highest priority) |	Walks to git root |
| AGENTS.override.md |	Personal, per-directory override of AGENTS.md (typically gitignored) |	CWD at startup + subdirectories progressively |
| AGENTS.md |	Project instructions, conventions, architecture |	CWD at startup + subdirectories progressively |
| CLAUDE.md	| Claude Code context files (also detected)	| CWD at startup + subdirectories progressively |
| SOUL.md	| Global personality and tone customization for this Hermes instance |	HERMES_HOME/SOUL.md only |
| .cursorrules |	Cursor IDE coding conventions |	CWD only |
| .cursor/rules/*.mdc |	Cursor IDE rule modules |	CWD only |

Ключевыми файлами здесь являются файлы `SOUL.md` и `AGENTS.md`/`HERMES.md`.

`SOUL.md` существует всегда, в нем определяются обязательные инструкции для модели, которые вставляются в начало каждой сесиии. В этом файле прописываются тон общения, персонализация, основные шаблоны для ответов на вопросы пользователя. Для каждого профиля файл SOUL.md может быть свой, изменить его также можно в GUI через эту кнопку:

  <img src="./images/hermes_setup_22.png" width="70%" alt="SOUL">
</p> 
<p align="center">
  <img src="./images/hermes_setup_23.png" width="70%" alt="SOUL">

Начинать работу можно с файла SOUL.md по умолчанию. Примеры SOUL.md приведены в папке `soul.examples`.

> [!WARNING]
> Не помещайте в SOUL.md пути к файлам/папкам, временные инструкции для проекта, соглашения, которые актуальны только для части ваших запросов.

`AGENTS.md`/`HERMES.md` - это необязательные файлы, которые располагаются в каталоге, с файлами которого вы собираетесь работать через агента Hermes. Как правило, в одном из этих файлов описывается суть проекта, архитектура, принятые соглашения по работе с файлами проекта и т.д. В общем случае это важно для работы с программным кодом, но может быть полезно и для каталогов, где есть много рабочих файлов с фиксированной структурой документов, а также правила их формирования, которые можно описать внутри данных файлов.

## 4. Профили (Profiles)
> [!NOTE]
> Для понимания необходимости использвания профилей нужно учитывать, что в каждом профиле можно задать стиль общения с моделью (через SOUL.md), а также в каждом профиле может существовать свой собственный список Capabilities (всего того, что агент дает модели - информацию о внешнем мире и средства для взаимодействия с другими системами).

В общем случае, профили могут использоваться для переключания между различными режимами работы агента. Например, это может быть агент-исследователь (для проработки какой-либо темы), агент-программист, агент-маркетолог и т.д. 
В каждом профиле определяются целевые средства для эффективного выполнения задачи из определенной области. Иметь одного универсиального агента можно, но здесь начинают влиять текущие ограничения работы с моделями.
> [!WARNING]
> Если в рамках одного профиля определять много коннекторов, MCP подключений, скилов/навыков, tools, то в каждый запрос к модели агент будет вставлять краткое описание каждого из таких capabilities, что будет съедать много входных токенов и в общем случае модель может потеряться в выборе конкретного средства для реализации запроса пользователя. Т.е. будет потрачено больше токенов для уточнения задачи и к конечному результату модель придет за большее количество шагов (выходных токенов).

> [!IMPORTANT]
**Общая рекомендация - давать модели в рамках одного профиля только тот список Capabilities, который нужен для выполнения конкретного сценария** - например, создания портфолио для нового клиента и создания на базе этой информации краткой презентации.

## 5. Проекты (Projects)
Project в Hermes Agent позволяют создать пространство для хранения данных в виде каталогов, которое будет использоваться разными сессиями, в том числе, при перезгрузках оболочки или запуска подагентов. Технически, запросы в модель можно выдавать и без создания проектов. Но с проектами сценарии работы с моделями могут быть сгруппированы в рамках проекта, который, в свою очередь, предоставит необходимые данные для успешного выполнения запросов.

### 6.1. Skills (Навыки)
Одно из наиболее используемых средств в современной работе в агентском ПО. Навык - это записанная в файле последовательность шагов для получения конкретного результата. Пример простого файла SKILLS.md с навыком `simple-replay` ([формальные требования к файлу SKILLS.md](https://agentskills.io/skill-creation/quickstart)):
```
---
name: simple-reply
description: Помогает составить краткий и вежливый ответ на сообщение пользователя.
version: 1.0.0
tags:
  - communication
  - writing
---

# Задача
Нужно сгенерировать ответ на сообщение пользователя.

# Как действовать
1.  Проверь, есть ли в сообщении ключевое слово (например, «спасибо», «привет», «давай»). Если таких слов нет — не используй этот навык.
2.  Сформулируй ответ лаконично, без лишних деталей.
3.  В конце добавь вежливую фразу, например: «Если нужно что-то уточнить или добавить — напиши, я с радостью помогу».

# Пример
Если пользователь написал: «Спасибо за помощь, теперь можно я попробую оформить заявку?», навык должен ответить: «Конечно! Если возникнут сложности — пишите, разберусь вместе с вами.»
```
Теперь, если разместить этот файл в соответсвующем месте, агент возьмет строки из полей `name` и `description` и вставит их в первоначальный запрос пользователя к модели. Если файлов будет несколько, все соответствующие строки из каждого файла будут вставлены в запрос к модели. Модель будет учитывать эту информацию для принятия решения о дальнейших действиях. Если описание какого либо навыка по мнению модели поможет ответить пользователю, то ответ модели будет содержать запрос в агентское ПО на получение полного текста навыка, по которому модель станет действовать, в том числе, поручая агентскому ПО задачи на выполнение каких-либо действий (выполнить скрипт, команду, использовать tools и т.д).

#### 6.1.1. Местонахождение файлов SKILLS.md
Глобальный набор скилов  Hermes Agent находится в `~/.hermes/skills/` (в macOS и Linux) или `%HERMES_HOME%\skills\` (в Windows).
Для каждого профиля есть своя собственная папка skills. Наборы папок, содержащих данные навыка, могут быть для удобства сгруппированы в папки верхнего уровня
Также агент ищет каталоги `.hermes/skills/` и `.agents/skills/` в корневых каталогах, которые включены в проект, из которого запускается сессия к модели. Однако найденные в таком местоположении навыки автоматически не запускаются, т.к. каталог может быть скачан/синхронизирован из внешенго источника. В этом случае Hermes Agent спрашивает, доверять ли этому источнику для загрузки навыков.
Дополнительно, навыки могут быть загружены из внешних каталогов, которые были сконфигурированы для данного ПО в config.yaml.

#### 6.1.2. Использование навыков
Технически имя установленного навыка можно не указывать, в этом случае есть вероятность, что модель автоматически выберет нужный и тех, что уже присусттвуют в профиле. Однако для полного контроля желательно указывать, какой именно навык нужно использовать в данной сессии к модели. В этом случае навык указывается через системную команду к Hermes Agent - `/<skill_name> <user_input>`. В упрощенном варианте можно написать текстом - `используя навык xxx, сделай yyy`

#### 6.1.4. Самостоятельное создание навыка
Если вы постоянно выполняете одну и ту же последовательность действий, например, поискать в интернете информацию, сохранить данные в файл, создать краткую сводку, то можно оформить эти действия в навык - Hermes Agent сам создаст необходимое описание и сохранит его в файл. Встроенная для этого  команда `/learn` ([Документация](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills#learning-a-skill-from-sources-learn)). Примеры такой команды:
```
# A local SDK or doc directory — read with read_file / search_files
/learn the REST client in ~/projects/acme-sdk, focus on auth + pagination

# An online doc page — fetched with web_extract
/learn https://docs.example.com/api/quickstart

# The workflow you just walked the agent through in this conversation
/learn how I just deployed the staging server

# Pasted notes / a described procedure
/learn filing an expense: open the portal, New > Expense, attach the receipt, submit

# A whole book, paper stack, or large docs corpus — becomes a knowledge-base skill
/learn ~/books/designing-data-intensive-applications.pdf
```

> [!TIP]
> У Hermes Agent есть обширный набор команд, которые запускаются через слэш. Как правило, полный потенциал работы с такими командами раскрывается при работе в командной строке. При использовании десктопного приложения можно команды для работы Hermes описывать обычным языком, например, `сохрани последовательность действий в данной сессии как скил xxx`.

#### 6.1.5. Автоматическая очистка пользовательских навыков
В Hermes существует технология Curator ([справка](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator)), которая управляет навыками, которые были созданы вручную.
Curator — это фоновый процесс обслуживания навыков, созданных Hermes Agent самостоятельно или под управлением ползовательсткого запроса. Несколько фактов об этом процессе:
 - его основная цель — предотвратить замусоривание каталога узкоспециализированными дубликатами навыков, возникающими в цикле самосовершенствования;
 -система отслеживает частоту использования навыков и переводит их из состояния «активный» в «устаревший», а затем в «архивный»;
 - по умолчанию Curator управляет только навыками агента, но может быть настроен на архивацию неиспользуемых встроенных навыков;
 - инструмент никогда не удаляет данные автоматически, а лишь перемещает их в папку архива для возможности восстановления;
 - запуск процесса происходит автоматически при соблюдении условий интервала (по умолчанию 7 дней) и периода бездействия агента;
 - первая фаза работы детерминирована: она помечает навыки как устаревшие через 14 дней или архивирует их через 30 дней бездействия. Вторая, опциональная фаза использует LLM для анализа, объединения перекрывающихся навыков в общие «зонтичные» структуры или их исправления.

### 6.2. Tools
Tools (инструменты) - это встроенные подключаемые конмпоненты Hermes Agent, которые поддерживаются создателями программы. С их помощью Hermes Agent получает возможность работать с командной строкой, браузером, распознавать картинки и речь и т.д. Их можно включать по необходимости для своего профиля.

### 6.3. Connectors
Коннекторы - это связь с внешним миром, как правило, через специализированные MCP сервера. ## 8. Approval mode (Уровень разрешений на выполнение команд)
Каждое продвинутое агентское ПО может выполнять на вашем компьютере какие-либо действия по поручению модели. Это может касаться чтения содержимого файлов, создания и запуска скриптов на Python, работы с браузером и других, потенциально опасных действий.
В Hermes Agent есть следующие настройки, контролирующие данное поведение - Запрашивать подтверждение для всех действий, Не запрашивать подтверждение и Умный режим (по умолчанию).

## 9. Механизм памяти
Для понимания конценпции можно почитать https://djd1m.github.io/grokbot-vs-hermes/#hermes.
Несколько слоев памяти:
<p align="center">
  <img src="./images/hermes_setup_40.png" width="70%" alt="Memory">
</p>

На первом слое (самом быстром) находятся два файла (уникальных для каждого профиля) - MEMORY.md для технических фактов об окружении и USER.md для профиля и предпочтений пользователя.

Для каждого файла установлены строгие лимиты по количеству символов, чтобы не перегружать системный промпт (данные лимиты можно менять через настройки).

Данные из памяти внедряются в системный промпт в виде «замороженного снимка» только в момент старта сессии.

Агент самостоятельно управляет записями через инструмент memory, который позволяет добавлять, заменять или удалять данные.

В памяти хранятся только высокосигнальные факты: настройки проекта, привычки пользователя и извлеченные уроки.

На втором уровне памяти агент может вызвать session_search, который обеспечивает неограниченный поиск по истории всех прошлых диалогов.
