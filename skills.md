## Что такое skill для LLM

**Skill (скилл)** — это готовый «модуль навыка» для языковой модели: набор чётких инструкций, правил и (при необходимости) вспомогательных файлов, который подсказывает ИИ, как решать конкретную типовую задачу в определённом стиле.

---

## Как устроены скиллы

Типичный скилл — это папка с файлами, где есть:

* **Файл с инструкцией** (часто в формате Markdown или YAML) — в нём описано, что должен делать скилл, какие фразы его активируют, какой формат ответа нужен, какие ограничения соблюдать.
* **Метаданные** — название, краткое описание, условия срабатывания, иногда указание на нужную модель или лимиты токенов.
* **Шаблоны, примеры, фрагменты кода** — чтобы модель выдавала результат в нужном виде и опиралась на правильные паттерны.
* **Ссылки на внешние репозитории** (как в твоём примере) — чтобы можно было брать актуальную версию скилла и держать его отдельно от основной системы.

В работе скилл не «вставляется» в чат каждый раз: он хранится отдельно и подгружается по триггеру (ключевой фразе, событию или явному вызову). Внутри сессии система может автоматически выбирать подходящий скилл под запрос пользователя.

---

## Для чего нужны скиллы

* **Стандартизировать ответы.** Чтобы ИИ каждый раз решал типовую задачу одинаково: по одному шаблону, в нужном формате, с нужными оговорками.
* **Автоматизировать рутину.** Не прописывать каждый раз «распиши по шагам», «сначала оцени риски», «потом дай следующий шаг» — это уже зашито в скилл.
* **Снижать ошибки и пропуски.** Например, скилл `os-what-could-go-wrong` принудительно заставляет модель проговорить риски перед важными действиями.
* **Делать общение удобнее для пользователя.** Одни скиллы упрощают формулировки, другие дают пошаговые инструкции, третьи визуализируют сложные вещи.
* **Упрощать поддержку и развитие.** Скиллы можно хранить в репозиториях (GitHub и т. п.), обновлять отдельно, делиться и переиспользовать в разных проектах.

Если скажешь, под какой сценарий ты хочешь собрать или подобрать скиллы (например, для отладки кода, управления задачами или обучения), подскажу, из каких компонентов лучше собрать такой набор.

## Как добавить новый skill в Hermes Agent

### Вариант 0: нужно найти скилл

Установить скилл [find-skills](skills/find-skills/) и с его помощью искать другие навыки командой `найди мне скилл для xxx`. (как установить скилл, см. следующие пункты).

---

### Вариант 1: если известно расположение скилла в репозитории на GitHub

Этот способ подходит, когда скилл уже есть в открытом репозитории.

1. **Определи путь к папке скилла.** В GitHub это не просто репозиторий, а конкретная подпапка (например, `skills/os-step-by-step/`). Убедись, что там есть файлы с логикой скилла (инструкции, шаблоны и т. п.).
2. **Скачай или скопируй файлы.** Есть два пути:
   * **Через git:** если у тебя настроен git, сделай `git clone` всего репозитория либо используй `sparse checkout`, чтобы забрать только нужную папку `skills/...`.
   * **Вручную:** зайди в браузерную версию GitHub, открой файлы скилла и скачай их, сохраняя структуру папок (важно, чтобы осталась вложенность `skills/название_скилла/`).
3. **Положи папку в локальную директорию skills.** У Hermes Agent должна быть рабочая папка, где лежит проект агента; туда в подпапку `skills/` помести скачанную папку скилла. Проверь, что структура выглядит так:  
   `./skills/os-step-by-step/...` (файлы скилла внутри).
4. **Проверь метаданные и зависимости.** Посмотри, нет ли в папке скилла файла с описанием (YAML/JSON/Markdown), где указаны триггеры, зависимости или требования к версии. Если есть внешние ссылки или скрипты — убедись, что они доступны в локальной среде.
5. **Перезапусти или перезагрузи скиллы в агенте.** В большинстве реализаций Hermes Agent нужно явно инициировать перечитывание скиллов (перезапуск сервиса либо команда вроде `agent reload skills` или аналогичная в CLI/конфигурации).
6. **Протестируй.** Проверь, срабатывает ли скилл по триггерным фразам и выдаёт ли ожидаемый результат.

---

### Вариант 2: родными средствами Hermes Agent (из GutHub)

Если навык находится в репозитории GitHub, установить его можно командой `/skills install <ссылка_на_github>`

---

### Вариант 3: родными средствами Hermes Agent (новый навык)

1. **Создай новую сессию и задай агенту задачу.** Шаги выполнения данной задачи будут использоваться для создания нового навыка.
2. **После получения результата напиши `/learn`** Это запустит процесс создания нового навыка.
или
2а. **После получения результата напиши `По результатам этой сессии создай навык xxx`**. 
3. **Проверь содержимое папки skiils для нового навыка** Отредактируйте при необходимости описание, последовательность действий и конечный результат в этом файле.

## Навыки агентов в папке skills

Коллекция скиллов, скопированная в папку [`skills/`](skills/) — всего 9 штук.  
Для каждого скилла указаны: локальная папка, оригинальный репозиторий на GitHub и зеркало (форк) в аккаунте [alavret](https://github.com/alavret) — если оно есть.

- **[find-skills](skills/find-skills/)** → помогает находить и устанавливать скиллы из открытого каталога экосистемы агентных скиллов (skills.sh) через CLI `npx skills find`. Перед рекомендацией проверяет качество скилла: число установок, репутацию источника и звёзды репозитория. Пригодится, когда нужно подобрать готовый скилл под новую задачу («найди скилл для X», «как сделать X»), а не писать свой с нуля.  
Оригинал: [vercel-labs/skills](https://github.com/vercel-labs/skills/tree/main/skills/find-skills).

- **[os-ask-simple](skills/os-ask-simple/)** → задаёт технические вопросы простыми словами. Пригодится, если нужно избегать сложной терминологии и делать общение максимально понятным.  
Оригинал: [kharmanskyi/open-steps](https://github.com/kharmanskyi/open-steps/tree/main/skills/os-ask-simple); зеркало: [alavret/open-steps](https://github.com/alavret/open-steps).

- **[os-check-work](skills/os-check-work/)** → проверяет работу, выполненную вне текущей сессии, и помогает подтвердить/объединить результаты. Пригодится при работе с несколькими сессиями или распределёнными задачами.  
Оригинал: [kharmanskyi/open-steps](https://github.com/kharmanskyi/open-steps/tree/main/skills/os-check-work); зеркало: [alavret/open-steps](https://github.com/alavret/open-steps).

- **[os-done-or-not](skills/os-done-or-not/)** → формирует отчёт о завершённой работе и отвечает, всё ли готово. Пригодится для быстрой проверки статуса и итогов сессии.  
Оригинал: [kharmanskyi/open-steps](https://github.com/kharmanskyi/open-steps/tree/main/skills/os-done-or-not); зеркало: [alavret/open-steps](https://github.com/alavret/open-steps).

- **[os-say-simple](skills/os-say-simple/)** → перефразирует уже сказанное в более простой и короткой форме. Пригодится, если ответ кажется слишком сложным или длинным.  
Оригинал: [kharmanskyi/open-steps](https://github.com/kharmanskyi/open-steps/tree/main/skills/os-say-simple); зеркало: [alavret/open-steps](https://github.com/alavret/open-steps).

- **[os-step-by-step](skills/os-step-by-step/)** → даёт пошаговые инструкции для действий пользователя (команды, клики, подтверждения и т. д.). Пригодится, когда нужно чётко понимать, что и в каком порядке делать.  
Оригинал: [kharmanskyi/open-steps](https://github.com/kharmanskyi/open-steps/tree/main/skills/os-step-by-step); зеркало: [alavret/open-steps](https://github.com/alavret/open-steps).

- **[os-what-could-go-wrong](skills/os-what-could-go-wrong/)** → подсвечивает риски и возможные проблемы перед важными, труднообратимыми решениями. Пригодится перед принятием решений вроде миграции, запуска, покупки, изменения цен.  
Оригинал: [kharmanskyi/open-steps](https://github.com/kharmanskyi/open-steps/tree/main/skills/os-what-could-go-wrong); зеркало: [alavret/open-steps](https://github.com/alavret/open-steps).

- **[os-whats-next](skills/os-whats-next/)** → подсказывает, что делать дальше, какие задачи остались или что блокирует работу. Пригодится, чтобы не терять фокус и видеть следующий шаг.  
Оригинал: [kharmanskyi/open-steps](https://github.com/kharmanskyi/open-steps/tree/main/skills/os-whats-next); зеркало: [alavret/open-steps](https://github.com/alavret/open-steps).

- **[visual-explainer](skills/visual-explainer/)** → генерирует HTML‑визуализации для систем, кода, планов и технических концепций. Пригодится, если визуальное объяснение помогает лучше понять структуру или процесс.  
Оригинал: [nicobailon/visual-explainer](https://github.com/nicobailon/visual-explainer/tree/main/skills/visual-explainer).
